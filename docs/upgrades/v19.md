# Upgrade to Umbraco 19

From Umbraco Commerce `[18.0.0, 18.999.999)` (CMS 18) to Umbraco Commerce `19.0.0-beta.1` (CMS `19.0.0-beta1`, tag `release-19.0.0-beta1`).
Branch `v19/topic/cms-19-upgrade` → PR into `release/19.0.0`, both cut from `main` (`8bdddab`).

**Targets CMS release:** `release-19.0.0-beta1`, via Umbraco Commerce `19.0.0-beta.1` (MyGet `umbracoprereleases`, already in `NuGet.config`). The package's own version is `19.0.0-beta.1`.

The package depends only on `Umbraco.Commerce.Core` and `Flurl.Http` (its own REST client for the Nets Easy API, no Nets SDK), never on `Umbraco.Cms.*` directly, so the CMS breaking changes reach it only through Commerce. Commerce's own v19 inventory (Core repo, `docs/upgrades/v19.md`) and the Stripe provider's v19 upgrade are the sources for those.

Found by the new client tests: `NetsEasyClient.CancelPaymentAsync` parsed the response as JSON, but Nets answers a cancel with 204 No Content, so every cancel threw, was logged, and left the order uncancelled in Commerce (Nets had cancelled it). Read the body as text instead; the signature is unchanged.

## Decisions

- Majors are the time to take third-party majors (maintainer, 30-10-2026). Flurl.Http has none.
- Add tests wherever they can run without Nets credentials (maintainer, 30-10-2026).
- Fix the cancel bug in this upgrade, as a separate commit, since the test that found it is part of task 2 (02-11-2026).

## Breaking changes for consumers

- Requires Umbraco Commerce 19 (.NET 11).
- `NetsEasyClient.CancelPaymentAsync` now returns the raw response body (an empty string for 204) instead of throwing. Same signature.
